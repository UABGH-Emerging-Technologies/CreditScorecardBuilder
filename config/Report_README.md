# Credit-Risk Scorecard Report  
_generated by the Credit-Score Risk-Model Builder created by the Data Science team in the Department of Anesthesia and Perioperative Medicine at the University of Alabama at Birmingham_

**Welcome!**
This folder bundles everything produced by one run of the scorecard-building pipeline: model metrics, diagnostic graphics, the full Word document report, a ready-to-use interactive Excel calculator, and supporting data tables.  Use this `README.md` to get oriented with the various output.

## 3. What’s Inside Each File

### 3.1 Figures (`figures/`)

| File | What it shows | Why it matters |
|------|---------------|----------------|
| **`auc_roc.png`** | ROC curve + AUC for train & test | Global discrimination power (1 = perfect, 0.5 ≈ random). |
| **`auc_pr.png`** | Precision-Recall curve | More revealing than ROC when classes are highly imbalanced. |
| **`cap_curve.png`** | Cumulative Accuracy Profile | Visualises lift vs. random selection, helps pick score cut-offs. |
| **`ks_statistic.png`** | Empirical CDFs & KS distance | Maximum separation of good vs. bad; used in many credit policies. |
| **`score_distribution.png`** | Score histograms for event vs. non-event | Sanity-check separation and look for multi-modality. |
| **`shap_all_features.png`** | SHAP summary for every feature | Feature importance + directionality across full model. |
| **`shap_top10_features.png`** | Same but top-10 only | Quick view of the biggest drivers. |
| **`shap_decision_10_all/top10*.png`** | Decision plots at 10 % bad-rate threshold | How cumulative SHAP values drive risk decisions. |
| **`shap_decision_20_all/top10*.png`** | Same at 20 % threshold | Sensitivity check at a looser cut-off. |
| **`threshold_10_percent.png`** | Records exceeding the 10 % score threshold | Operational reference for conservative cut-off. |
| **`threshold_20_percent.png`** | Records exceeding the 20 % threshold | Operational reference for more aggressive cut-off. |

### 3.2 Data tables (`data/`)

| CSV | Columns (abridged) | Purpose |
|-----|--------------------|---------|
| **`metrics_comparison.csv`** | `auc_roc, auc_pr, ks_stat, cap_curve` for **train / test** | Side-by-side snapshot of headline metrics. |
| **`psi_table.csv`** | `Bin, Count_A, Count_E, EventRate_A, EventRate_E, statistic, p_value` | Population Stability Index (PSI) comparing training (A) vs. evaluation/test (E) score distributions. |
| **`scorecard_table.csv`** | `Variable, Bin id, Bin, Count, Non-event, Event, Event rate, WoE, IV, Points, …` | Full scorecard definition—exactly what is loaded into the Excel calculator. |

> Tip: All CSV files are comma-separated with UTF-8 encoding and header row—ready for Excel, R, Python, or BI tools.

### 3.3 Interactive tools & narrative files

| File | Description |
|------|-------------|
| **`Scorecard_Calculator.xlsx`** | A blue-cell / pull-down Excel tool. Select a borrower’s characteristics to obtain the total score, risk probability, and risk band instantly (no macros required). All bin borders and points come from `scorecard_table.csv` to avoid drift. |
| **`Credit_Scorecard_Report.docx`** | 15–25 page Word document combining the narrative, methodology, every figure, and key tables. Ideal for audit or management presentation. |
| **`Summary.txt`** | Plain-text executive digest: top metrics, major risk drivers, training vs. test similarity, and usage advisory (e.g., “moderately reliable, suitable for risk assessment”). |

## 4. Interpreting Key Metrics

| Metric | Good value | Interpretation |
|--------|------------|----------------|
| **AUC-ROC** | > 0.80 | Probability a random bad score ranks higher than random good. |
| **AUC-PR** | Context-specific | Focused on precision at different recall levels; useful under imbalance. |
| **KS Statistic** | 0.3–0.5 in credit | Max vertical distance between CDFs; higher = better separation. |
| **CAP / Gini** | > 0.4 | Area between model and random lines; synonymous with AUC. |
| **PSI** | < 0.10 ideal | Stability of score distribution; > 0.25 suggests model drift. |

## 5. Re-producing / Updating the Report

1. **Run the model-builder script** with your new data.  
2. All artifacts listed above are regenerated in a fresh timestamped folder.  
3. Attach the new `Scorecard_Calculator.xlsx` to downstream systems or credit officers.  
4. Archive previous folders for tracking model evolution and stability.
